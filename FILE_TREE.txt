API Endpoints
=============

Events:
  GET    /api/events              → List all events
  GET    /api/events/<id>         → Get event by ID
  POST   /api/events              → Create new event
  PUT    /api/events/<id>         → Update event
  DELETE /api/events/<id>         → Delete event
  PATCH  /api/events/<id>/notes/<note_id> → Update note status

Categories:
  GET    /api/categories          → List all categories
  GET    /api/categories/<id>     → Get category by ID
  POST   /api/categories          → Create new category
  PUT    /api/categories/<id>     → Update category
  DELETE /api/categories/<id>     → Delete category


Data Flow
=========

User Action → Frontend JS → API Request → Flask Route → 
Storage Utility → JSON File → Response → JS Update → 
DOM Render → User Sees Change

Example: Creating an Event
1. User clicks "Add Event" button (main.js listens)
2. Modal opens (modals.js)
3. User fills form and submits (event-crud.js)
4. API POST request (utils.js apiRequest)
5. Flask receives at /api/events (api/events.py)
6. Event model validates data (models/event.py)
7. Storage writes to events.json (api/storage.py)
8. Response sent back to frontend
9. Events reloaded (events.js)
10. Calendar re-rendered (event-renderer.js)
11. User sees new event


Development Workflow
====================

1. Start server:
   $ python app.py

2. Flask runs in debug mode (auto-reload on Python changes)

3. Edit files:
   - Python: Auto-reloads server
   - HTML/CSS/JS: Refresh browser

4. Check console:
   - Terminal: Python errors
   - Browser: JavaScript errors

5. Test features:
   - Create/edit/delete events
   - Manage categories
   - Drag and resize
   - Check persistence


Production Notes
================

For production deployment:

2. Set strong SECRET_KEY
3. Use production WSGI server (gunicorn, uWSGI)
4. Add database instead of JSON files
5. Add authentication
6. Add HTTPS
7. Minify CSS/JS
8. Add caching headers
9. Set up backups
